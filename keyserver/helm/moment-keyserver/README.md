# Moment keyserver Helm chart

This chart deploys the Moment backend, a separate daily settlement worker, and a CloudNativePG PostgreSQL cluster. Photos are stored in a private Cloudflare R2 bucket. The default topology uses two backend replicas and three PostgreSQL instances with synchronous replication.

## Prerequisites

- Kubernetes 1.28 or later, Helm 3 or 4, and a suitable persistent storage class.
- CloudNativePG installed with its CRDs and permissions for the application namespace. Check the selected operator's Kubernetes compatibility.
- A built keyserver image available in your registry.
- A private R2 bucket and credentials scoped to that bucket.
- A deployed Solana program whose publication authority matches the provided keypair.
- Existing application secrets and, when enabling ingress, a TLS secret.

The chart does not install operators or CRDs. PostgreSQL backups additionally require the Barman Cloud CNPG-I plugin and its `ObjectStore` CRD. Follow the [plugin installation instructions](https://cloudnative-pg.io/plugin-barman-cloud/docs/installation/), including its cert-manager prerequisite. PostgreSQL metrics require Prometheus Operator's `PodMonitor` CRD.

## Provision secrets

Create an existing Secret, normally `moment-keyserver-secrets`, in the release namespace. Credentials are not generated by the chart or stored in Helm values.

| Secret key | Content |
| --- | --- |
| `rpc-url` | Solana HTTPS RPC URL |
| `key-encryption-key` | Base64-encoded random 32-byte master key |
| `publication-authority.json` | Dedicated Solana keypair, a JSON array of 64 bytes |
| `crank.json` | Separate settlement keypair, funded with SOL; required when the crank is enabled |
| `r2-access-key-id` | R2 S3 access key ID |
| `r2-secret-access-key` | R2 S3 secret access key |

Use your secret manager or protected files. For example, from the repository root:

```sh
kubectl create namespace moment
kubectl -n moment create secret generic moment-keyserver-secrets \
  --from-file=rpc-url=./secrets/rpc-url \
  --from-file=key-encryption-key=./secrets/key-encryption-key \
  --from-file=publication-authority.json=./secrets/publication-authority.json \
  --from-file=crank.json=./secrets/crank.json \
  --from-file=r2-access-key-id=./secrets/r2-access-key-id \
  --from-file=r2-secret-access-key=./secrets/r2-secret-access-key
```

Text-value files must not include a trailing newline. All backend replicas use the same encryption master key. Preserve it and the publication keypair outside the cluster, separately from database backups. Changing the master key does not migrate existing encrypted keys.

## Configure and install

Create a values file containing deployment settings, without credentials:

```yaml
image:
  repository: ghcr.io/YOUR_ACCOUNT/moment-keyserver
  tag: "0.1.0"
config:
  network: devnet
  programId: YOUR_PROGRAM_ID
  authOrigin: https://YOUR_BACKEND_HOST
  r2Endpoint: https://YOUR_ACCOUNT_ID.r2.cloudflarestorage.com
  r2Bucket: moment-devnet
  allowUncalibratedModeration: true
  trustedProxyCidrs: ["10.1.2.3/32"]
postgresql:
  storage:
    size: 20Gi
    storageClass: YOUR_STORAGE_CLASS
ingress:
  enabled: true
  className: nginx
  host: YOUR_BACKEND_HOST
  tlsSecretName: moment-tls
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: "12m"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "60"
```

Replace every placeholder and the proxy CIDR with your actual configuration. The experimental moderation bypass is for devnet only; it must remain disabled on mainnet. The ingress CIDRs must identify the proxies that connect to the backend, not all clients or the entire pod network.

```sh
helm lint ./keyserver/helm/moment-keyserver -f values-deployment.yaml
helm template moment ./keyserver/helm/moment-keyserver -n moment \
  -f values-deployment.yaml > /tmp/moment-rendered.yaml
kubectl -n moment apply --dry-run=server -f /tmp/moment-rendered.yaml
helm upgrade --install moment ./keyserver/helm/moment-keyserver -n moment \
  -f values-deployment.yaml --wait --timeout 15m
```

Ingress is disabled by default. Enabling it requires an existing TLS secret and a non-empty trusted proxy list. `config.authOrigin` must exactly match the public HTTPS origin, without a path. Configure proxy request limits of at least 12 MiB and a timeout of at least 60 seconds.

The ingress must overwrite or correctly append `X-Forwarded-For`. The backend resolves it from right to left to the first untrusted peer. Its request quota is per pod; configure additional proxy limits if it must be shared across replicas.

## PostgreSQL

The default cluster name is `<release>-moment-keyserver-pg`. The backend connects to its read/write service with `PGSSLMODE=verify-full`, using the CNPG CA secret. Database credentials normally come from CNPG's generated application secret. `postgresql.existingSecret` can provide an existing `kubernetes.io/basic-auth` secret with `username` and `password` matching the configured database owner.

The application role must be able to create tables and indexes. Migrations run automatically under a PostgreSQL lock. Changing bootstrap values does not migrate an initialized database.

`config.databaseMaxConnections` defaults to ten per backend pod. Account for replicas, rolling updates, administration, and other clients within PostgreSQL's connection budget. The HPA requires metrics-server. The PDB protects against voluntary disruptions; it does not guarantee continuous availability.

For an external PostgreSQL service:

```yaml
postgresql:
  enabled: false
externalPostgresql:
  host: YOUR_POSTGRES_HOST
  port: 5432
  database: moment
  existingSecret: moment-external-db
  caSecret: moment-external-db-ca
  caKey: ca.crt
```

The external credential secret must contain `username` and `password`. TLS remains verified. Configure external synchronous replication independently.

### Durability

By default, `postgresql.synchronousReplication: true` configures `ANY 1` with `dataDurability: required`. A commit waits for WAL persistence on a standby, protecting photo keys recorded before returning a Solana cosignature against loss of the primary alone.

If no standby is available, writes can wait or time out. Local single-instance testing requires an explicit `postgresql.synchronousReplication: false`. Multiple-node failures and failover must be validated on the target cluster; replication does not replace backups. See [CNPG replication documentation](https://cloudnative-pg.io/docs/1.28/replication/).

## Backups and recovery

Use a separate private bucket and separate credentials for PostgreSQL backups. The chart rejects sharing the application's bucket or credential secret. The backup secret contains `access-key-id` and `secret-access-key`.

```yaml
postgresql:
  backup:
    enabled: true
    endpointURL: https://YOUR_ACCOUNT_ID.r2.cloudflarestorage.com
    destinationPath: s3://moment-postgres-backups/deployment
    existingSecret: moment-postgresql-backup
    retentionPolicy: 30d
    schedule: "0 0 3 * * *"
```

The six-field schedule includes seconds. The chart creates a Barman `ObjectStore`, enables continuous WAL archiving, and creates a plugin-based `ScheduledBackup`. An initial backup is requested immediately. R2 uses region `auto` and the configured S3 checksum settings.

```sh
kubectl -n moment get cluster,scheduledbackup,backup
kubectl -n moment describe cluster moment-moment-keyserver-pg
kubectl -n moment get objectstore moment-moment-keyserver-pg-backup
```

Database backups do not include photo objects or the encryption master key. Preserve those independently and test their recovery together. Validate credentials, retention, and restore behavior against your real bucket.

Restore into a new CNPG cluster using `bootstrap.recovery` and the source `ObjectStore`, following the [Barman recovery procedure](https://cloudnative-pg.io/plugin-barman-cloud/docs/usage/#restoring-a-cluster). Do not reuse the source archive prefix as the new write destination. After validation, point an application release at the recovered cluster through `externalPostgresql`. The chart does not automatically convert an existing cluster into a recovered cluster.

## Network and monitoring

`networkPolicy.enabled=true` selects backend pods. Its default rules allow incoming port 8080 from the same namespace and outgoing DNS, PostgreSQL, and HTTPS traffic. Configure `ingressFrom` for your ingress controller and `additionalEgress` for external PostgreSQL or custom DNS.

```yaml
networkPolicy:
  enabled: true
  ingressFrom:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: ingress-nginx
      podSelector:
        matchLabels:
          app.kubernetes.io/component: controller
```

CNPG pods need their own rules preserving operator, replication, metrics, and backup traffic. In a namespace with existing deny-all policies, allow those separately. Verify kubelet probe access for your CNI. Standard NetworkPolicy cannot filter HTTPS by hostname.

`/healthz` checks the process; `/readyz` checks PostgreSQL. Startup validates ONNX and the Solana configuration before opening HTTP. The startup probe permits five minutes. The backend runs without an automatically mounted Kubernetes token, uses a read-only root filesystem, and has a bounded temporary volume.

`postgresql.monitoring.enabled` creates a PodMonitor; configure its labels for your Prometheus selector. Backup plugin monitoring is configured separately.

## Daily settlement worker

A separate Deployment runs `moment-keyserver crank` with one replica and the `Recreate` strategy. It settles missed days at 00:05 UTC, retries every fifteen minutes through the previous pool's closure plus five minutes, pays closed-pool claims, and closes check-ins from two days earlier to return rent.

The worker receives only the network, program, RPC endpoint, and its dedicated keypair. It does not mount the publication key, database credentials, or moderation model. Keep its SOL balance funded. Its key can use a separate secret through `crank.existingSecret`; disable it with `crank.enabled=false` if settlement is handled elsewhere.

## Updates and removal

ConfigMap changes trigger a rollout through a checksum annotation. After rotating environment secrets, restart the backend Deployment:

```sh
kubectl -n moment rollout restart deployment/moment-moment-keyserver
```

By default, `postgresql.keep=true` retains the CNPG `Cluster` and backup `ObjectStore` on Helm uninstall. Database pods, PVCs, and WAL archiving can remain active. The Helm-managed backup scheduler is removed. For permanent removal, verify backups and stop writes before explicitly deleting retained resources under your retention policy.

Keep the release and cluster names stable during upgrades: renaming them can create a second database cluster.

## Validation

```sh
uv run --with pyyaml --with jsonschema python \
  keyserver/helm/moment-keyserver/tests/render.py
```

Add `--crds` to validate rendered resources against downloaded official CRD schemas. These tests cover default deployments, backups, ingress, autoscaling, network policy, external PostgreSQL, and invalid configurations. They do not replace server-side admission checks, real storage provisioning, failover exercises, or backup restoration on the target cluster.
